# 도메인 로직 구현 규칙

개발 문서 10장: "레이팅 계산, 팀 밸런스는 화면과 분리된 순수 함수로 만들고 단위 테스트를 작성합니다. 한번 잘못 반영된 레이팅은 되돌리기 어렵습니다." 이 스킬은 그 지침을 구체화한다.

## 1. 구조

```
packages/core/src/
  config.ts       조정 가능한 상수 (K, 시드, 노쇼, 리셋 비율, 포지션 비용)
  rating.ts       expectedScore, updateTeamRatings, seedFromTier, kFactor, softReset
  balance.ts      balanceTeams → 상위 3안
  ranking.ts      tierScore, activityPeriod(KST 주/월 경계)
  penalty.ts      isScrimBanned
  index.ts
packages/core/test/*.test.ts
```

## 2. 순수 함수 규칙

- 입력은 원시값·평범한 객체, 출력도 새 객체. 인자를 변경하지 않는다.
- 현재 시각은 `now: Date` 인자로 받는다. `Date.now()`, `Math.random()`을 쓰지 않는다. 같은 입력이면 항상 같은 결과가 나와야 레이팅 분쟁 때 재계산으로 검증할 수 있다.
- 동점 정렬은 결정적으로(예: user_id 오름차순) 처리한다. 밸런스 상위 3안이 실행마다 바뀌면 방장이 혼란스럽다.
- 문서의 "제안값"은 모두 `config.ts`에 기본값으로 두고, 함수는 `config`를 선택 인자로 받는다.

## 3. 계산 명세

정확한 수식, 기본값, 문서가 비워 둔 부분의 해석은 `references/formulas.md`에 있다. 구현·테스트 전에 반드시 읽는다.

## 4. 테스트 작성 기준

각 함수에 대해 다음을 포함한다.

| 종류 | 예 |
| --- | --- |
| 문서 예시값 | 실버 1000 / 골드 1200 / 플래 1400 시드, 동일 레이팅 기대 승률 0.5 |
| 보존 성질 | 같은 K를 쓰는 두 팀 갱신 시 레이팅 총합 변화 0 |
| 경계값 | 내전 9경기 vs 10경기 K, 노쇼 30일 경계 정확히 30일 전, 일요일 23:59 KST vs 월요일 00:00 KST |
| 조합 | 10명 → 126 분할 모두 탐색, 결과 3안이 비용 오름차순, 중복 안 없음 |
| 예외 입력 | 10명이 아님, 포지션 없는 게임, 희망 포지션 미입력 |

밸런스는 결과 안의 팀 합계를 독립적으로 다시 계산해 비용이 맞는지 검증하는 속성 테스트를 하나 둔다.
