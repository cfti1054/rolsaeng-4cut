## 제외

- 티어·ELO 랭킹 화면과 랭킹 캐시, 홈 대시보드 → S4 (ELO 랭킹의 「5경기 이상」 규칙도 S4)
- 시즌 종료 처리(최종 순위 스냅샷, 뱃지, 소프트 리셋) → S4 이후. S3는 시즌 테이블 조회만
- 결과 이의 제기(disputes)·승인된 결과 되돌리기·관리자 승인 대기 화면 → S6. S3에서 운영진은 상세 화면에서 승인·반려한다
- 디스코드 알림(결과 승인 알림 등) → 알림 기능 슬라이스
- 토너먼트 대진(목업 「토너먼트 드래프트」) → P2

## 메인이 정한 기본값 (사용자 확인 전, 보고서에 명시)

1. 시드 티어 표: 아이언 600, 브론즈 800, 실버 1000, 골드 1200, 플래티넘 1400, 에메랄드 1600, 다이아몬드 1800, 마스터 이상 2000(디비전·LP 무시). lol·tft는 대표 계정의 해당 게임 티어, 스팀 게임은 항상 1000. 시드는 해당 시즌 레이팅 행을 처음 만들 때 한 번만 쓴다.
2. K 판정의 「내전 10경기 미만」은 해당 게임의 승인된 rated 내전 경기 수(모든 시즌 합계)로 센다.
3. 개인 순위 게임은 참가자 모든 쌍을 1:1 대결로 보고(위가 승리), K를 (N−1)로 나눠 합산한다. 동순위 없음.
4. 팀 구성은 정원이 찬 뒤(`full`) 또는 진행 중(`playing`)이고 결과가 제출되기 전까지 저장·변경할 수 있다. 팀 게임(`has_teams`)의 결과 제출에는 팀 구성이 필요하다. `auto_balance=false` 내전도 직접 팀 구성은 할 수 있다.
5. 밸런스 총 비용 = 전력 차 + λ × 포지션 비용. λ와 동점 처리는 architect가 정하고 설정값으로 분리하지 않아도 된다.
6. `rated=false` 내전도 결과 입력·승인 흐름은 같고 레이팅만 바뀌지 않는다.
7. 노쇼로 표시된 참가자와 팀에 배정되지 않은 참가자는 레이팅 반영 대상이 아니다. 노쇼 표시는 결과 승인 뒤에도 S2 규칙(시작 후 7일)을 따르며, 노쇼 표시가 이미 반영된 레이팅을 바꾸지는 않는다.
8. 결과 입력은 방장, 승인·반려는 운영진. 방장이 운영진이어도 자기 제출은 승인할 수 없다(다른 운영진 필요). 운영진은 방장 대신 결과를 입력할 수 있다(그 경우에도 본인 제출은 본인이 승인 불가).
9. 승인된 결과는 이 슬라이스에서 수정·취소할 수 없다.
10. 동시성: 같은 결과 이중 승인, 같은 사용자 레이팅 동시 갱신을 막는다(행 잠금 또는 `rating_history (scrim_id, user_id)` 유일 + 트랜잭션).

## 환경 제약 (이전과 동일)

- `corepack pnpm`. 이 PC에는 Docker·PostgreSQL·Redis 없음 → DB 통합 테스트는 작성만 하고 미실행.
- 커밋은 사용자가 직접 한다. 에이전트는 커밋하지 않는다.
- 배포는 Railway(Dockerfile). 새 환경 변수가 생기면 `.env.example`과 계약 환경 변수 표에 반영.
