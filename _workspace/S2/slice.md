## 인증 보완 (사용자 결정, S0·S1 계약 일부 변경)

1. **리프레시 토큰 교체를 하루 1회로.** 지금은 `/auth/refresh` 때마다 회전한다. 앞으로는 현재 토큰이 발급된 지 24시간(설정값) 미만이면 회전하지 않고 같은 토큰을 유지한다(새 Set-Cookie 없음). 회전 시 기존 재사용 감지·10초 유예(D26)는 그대로. 절대 만료(로그인 시점부터 30일)는 유지한다(사용자가 「마지막 사용부터 30일」은 선택하지 않음).
   - 이유: 회전된 새 토큰이 브라우저에 저장되지 못하면(응답 전 페이지 이탈 등) 다음 접속 때 옛 토큰이 재사용 감지에 걸려 로그인 전체가 끊긴다. 사용자 보고: 「접속할 때마다 로그인」, 「스팀 연동 후 재로그인」.
2. **스팀 연동을 팝업 창으로.** 「Steam으로 로그인」이 새 창에서 Steam OpenID를 진행하고, 콜백이 끝나면 팝업이 원래 창에 결과를 알리고 닫힌다. 원래 창은 새로고침 없이 계정 목록을 다시 불러온다. 팝업이 차단되면 지금처럼 같은 창 이동으로 대체한다. 결과 전달 방식(같은 오리진 postMessage + origin 검사, 또는 BroadcastChannel)은 architect가 정한다.

## 제외

- 팀 자동 밸런스, 결과 입력·승인, ELO 반영, 레이팅 그래프 → S3. 상세 화면의 밸런스·결과 영역은 빈 상태(자리만)
- 홈 대시보드의 모집 중 내전 카드 → S4
- 관리자 화면(노쇼 표시 UI 포함) → S6. S2는 노쇼 표시 **API**와 제한 로직만. 상세 화면에서 운영진에게 노쇼 표시 버튼을 보일지는 architect가 정함(간단하면 포함 가능)
- 디스코드 알림(내전 시작 30분 전 등) → 알림 기능 슬라이스
- 스팀 게임 내전의 게임 선택(어떤 스팀 게임인지)은 제목·규칙 텍스트로 대체(필요하면 architect가 선택 필드 제안)

## 메인이 정한 기본값 (사용자 확인 전, 보고서에 명시)

1. 노쇼 기준은 문서 7-4 그대로: 30일 안에 3회 → 7일 제한. 값은 설정값으로 분리.
2. 시작 시각은 현재보다 미래만 허용(최대 30일 뒤). 시작 시각이 지나면 참가·취소·대기 등록 불가.
3. 정원: 게임별 기본값과 범위(롤 10, 롤체 8, 스팀 2–16 등)는 architect가 games 행 속성을 활용해 정함. 롤 5:5는 10 고정 여부도 architect가 결정.
4. 방장은 자동으로 참가자 1번(포지션 선택 필요). 방장이 참가를 취소하려면 모집글 취소를 해야 한다(방장 위임은 범위 밖).
5. 같은 사용자가 같은 시간대에 여러 내전에 참가하는 것은 막지 않는다.
6. 동시성: 마지막 자리에 동시에 참가하면 한 명만 참가, 나머지는 대기열. DB 잠금 또는 조건부 갱신으로 보장(nestjs-backend 스킬 규칙).
7. 대기열 자동 참가 확정 시 포지션은 대기 등록 때 고른 희망 포지션을 그대로 쓴다.

## 환경 제약 (이전과 동일)

- `corepack pnpm`. 이 PC에는 Docker·PostgreSQL·Redis 없음 → DB 통합 테스트는 작성만 하고 미실행.
- 커밋은 사용자가 직접 한다. 에이전트는 커밋하지 않는다.
- 배포는 Railway(Dockerfile). 새 환경 변수가 생기면 `.env.example`과 계약 환경 변수 표에 반영.
