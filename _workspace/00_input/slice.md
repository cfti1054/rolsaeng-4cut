## 제외

- 활동·플레이타임 랭킹과 `/rankings/activity`·`/rankings/playtime` → S5. 화면 탭은 비활성 또는 「봇 연동 후 제공」 안내로 두고 가짜 숫자를 넣지 않는다
- 홈 음성 채널 접속 인원·이번 주 활동 멤버 → S5(봇 데이터). 값이 없는 카드는 숨기거나 「봇 연동 후」로 표시. 스파크라인·전주 대비 변화는 자료가 없으면 생략
- 패치·이벤트 → S6. 홈 영역은 안내 또는 숨김
- 라이엇 티어 변화 그래프, 업적·포인트(P2), 뱃지 상점
- 시즌 수동 생성·수정 등 관리자 화면 → S6

- 시즌 종료 처리(최종 순위 스냅샷, 뱃지 지급, 소프트 리셋)를 S4에 포함한다(2026-10-30).

## 메인이 정한 기본값 (사용자 확인 전, 보고서에 명시)

1. 티어 랭킹은 슬라이스 표대로 대표 계정(D56) 기준, 게임별(lol·tft) 솔로 랭크 큐. 언랭은 제외.
2. 뱃지는 게임별 시즌 최종 1·2·3위에 지급. 코드와 시드는 architect가 정한다(`badges` 시드, `user_badges` 유일 키 재사용).
3. 순위 변동(+/−)은 이전 캐시 스냅샷 대비가 아니라 안정적인 기준으로 계산한다. 기준은 architect가 정하되 5분마다 값이 흔들리면 안 된다. 기준 자료가 없으면 `—`로 표시한다.
4. 탈퇴·비활성 멤버는 랭킹에서 제외(기존 사용자 상태 규칙 재사용).
5. 시즌 종료 처리는 시즌 종료 시각 이후 주기 작업으로 실행하고, 시즌 판정은 S3 `resolveSeasonAt`·KST 규칙을 그대로 쓴다.

## 환경 제약 (이전과 동일)

- `corepack pnpm`. 이 PC에는 Docker·PostgreSQL·Redis 없음 → DB 통합 테스트는 작성만 하고 미실행. 마이그레이션은 prisma migrate diff로 일치 확인.
- 커밋은 사용자가 직접 한다. 에이전트는 커밋하지 않는다.
- 배포는 Railway(Dockerfile). 새 환경 변수가 생기면 `.env.example`과 계약 환경 변수 표에 반영.

## 메인이 정한 기본값 (사용자 확인 전, 보고서에 명시)

1. 패배 배율 기본 0.5, env `SCRIM_ELO_LOSS_RATIO`(0 이상 1 이하). 패배 변동 = 반올림(K × (0 − E) × 배율). 승리 쪽 식은 그대로. 개인 순위 게임은 합산 변동이 음수일 때 같은 배율을 곱한다.
2. 이미 승인된 경기의 rating_history와 현재 점수는 다시 계산하지 않는다. 배율은 변경 이후 승인부터 적용한다.
3. 호칭 변경은 화면만이다. DB enum `scrim_team`, API 값 `orange`, 코드 식별자는 유지한다(마이그레이션·API 계약 변경 없음). 팀 색은 레드 계열 토큰을 새로 두고, 경고 등 팀과 무관한 orange 토큰은 그대로 둔다.
4. ⓘ는 호버 + 키보드 포커스 + 터치 탭 모두 동작한다(모바일에는 호버가 없다). 숫자는 서버 설정값을 따르고 화면에 고정하지 않는다.
5. 위치: `/rankings` ELO 탭, 프로필 내전 레이팅 카드, 사이드바 내 ELO 근처 중 architect가 정한다. 시작 점수 규칙(티어 시드, 소프트 리셋)과 승패 점수 비대칭을 함께 설명한다.
6. 시작 점수 전원 1000 안은 사용자 결정 전이므로 현재 규칙(티어 시드)대로 설명한다.
